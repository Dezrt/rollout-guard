# Runbook: Rollout Guard не разрешил релиз

## Сначала определить тип результата

Перед любыми действиями нужно прочитать вывод Job или CI:

| Решение | Код | Что означает |
|---|---:|---|
| `promote` | 0 | Все проверки прошли |
| `rollback` | 2 | Нарушен SLO-порог или политика `on_no_data` |
| `error` | 1 | Данных недостаточно для решения |

`error` нельзя считать успешной проверкой. Кандидата стоит оставить на текущей
доле трафика либо откатить — в зависимости от политики конкретного сервиса.

## `rollback`: нарушен SLO

1. Записать версию кандидата и временное окно из отчёта.
2. Выполнить тот же PromQL в Prometheus с теми же границами времени.
3. Разбить результат по Pod, зоне и коду ответа, чтобы локализовать регрессию.
4. Сравнить кандидата со stable-версией.
5. Откатить релиз, если метрика остаётся за порогом.
6. Приложить JSON-отчёт и ссылки на дашборды к записи о deployment.

Частые причины: регрессия приложения, холодный кеш, изменение схемы данных или
слишком мало трафика на canary.

## `error`: результат не определён

### Prometheus недоступен

```bash
kubectl -n monitoring get endpointslices -l kubernetes.io/service-name=prometheus-server
kubectl -n monitoring get pods
kubectl -n monitoring logs deploy/prometheus-server --since=15m
```

Проверить DNS, NetworkPolicy, TLS trust, аутентификацию и заданный timeout.

### Запрос вернул несколько временных рядов

По умолчанию это ошибка. Нужно агрегировать результат в PromQL через `sum`,
`max` или `histogram_quantile`, пока проверка не начнёт возвращать один ряд.
`allow_multiple_series` стоит включать только тогда, когда reducer действительно
должен применяться ко всем точкам всех рядов.

### Запрос не вернул данных

Проверить labels у метрик кандидата, значение версии, scrape health и наличие
реального трафика на canary. Не стоит переключать `on_no_data` в `pass` только
для того, чтобы пропустить релиз.

### Пришёл `NaN` или бесконечность

Отношения можно защитить через `clamp_min()`. Для histogram нужно убедиться,
что нужные buckets вообще существуют. Неограниченные значения отклоняются,
потому что обычное сравнение с ними может дать вводящий в заблуждение результат.

## Ручной обход

Для обхода нужны ответственный, записанная причина, срок действия исключения и
заранее подготовленная команда отката. Флага `--force` в приложении нет
намеренно: bypass должен находиться в аудируемом approval flow системы доставки.
