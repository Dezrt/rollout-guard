# ADR 0001: запрашивать Prometheus напрямую

- Статус: принято
- Дата: 2026-07-29

## Контекст

После окна наблюдения delivery-пайплайну нужен однозначный ответ по canary.
Готовые сигналы уже есть в Alertmanager, но состояние алерта зависит от
интервала вычисления rules, длительности `for`, inhibition, grouping и
notification routing. Для оповещений это полезно, а повторить решение релизного
гейта с теми же входными данными становится сложнее.

## Решение

Rollout Guard обращается к Prometheus `query_range` API напрямую и сравнивает
результаты с явными порогами из версионируемого TOML-файла.

## Последствия

Плюсы:

- решение можно повторить с той же конфигурацией и временным окном;
- критерии релиза ревьюятся рядом с deployment-кодом;
- notification routing не влияет на результат.

Минусы:

- PromQL может дублировать уже существующий alert;
- приложению нужен сетевой и аутентификационный доступ к Prometheus;
- стоимость запросов нужно контролировать размером окна и шагом.

Дублирование принято осознанно: политика релиза и политика оповещений меняются
с разной скоростью и по-разному обрабатывают сбои.
