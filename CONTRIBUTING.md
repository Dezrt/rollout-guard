# Как внести изменение

Проект намеренно решает одну задачу: проверяет здоровье релиза по метрикам.
Если новая возможность начинает управлять трафиком или Kubernetes-объектами,
сначала стоит описать сценарий в issue и проверить, не относится ли он к
delivery-контроллеру.

## Локальная проверка

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -e .
make check
```

Если установлены Docker и Helm:

```bash
make docker-build
make helm-lint
make demo
```

В PR достаточно описать проблему, выбранное поведение и способ проверки.
Коммиты лучше оставлять небольшими и не смешивать в них несвязанные изменения.
